# Trace 数据格式

```text
<run>/meta.json
<run>/log.txt
<run>/calls/call_<序号>_tid<线程>_<记录数>r_<耗时>ms/
  trace.bin
  meta.json
  external_writes.bin    # 可选
  memory_snapshot.bin    # 可选
```

分析命令通常接收单次调用目录。采集中使用 `_pending_call_*`；回传失败保留 pending
和设备 spool，恢复后由 `finalize` 回填元数据并重命名。旧平铺格式仅用于读取兼容。

## trace.bin

小端、每条 272 字节，与 core `Record` 对应；寄存器均为指令执行前状态。

| 字段 | 类型 |
|---|---|
| `pc` | `u64` |
| `regs[31]` | `x0..x28, fp, lr`，各 `u64` |
| `sp` | `u64` |
| `nzcv` | `u32` |
| `inst` | `u32` |

无保留字段，不内嵌 SIMD/FP 或内存字节。记录数须与文件长度一致。

## 元数据与 sidecar

调用级 `meta.json` 保存记录数、线程、目标、模块映射、寄存器顺序、截断/丢弃信息及
sidecar 描述。地址用 `0x` 字符串，计数与长度用整数。旧字段缺失或 `null` 不能视为
已验证完整；格式变更须版本化并测试迁移。

`external_writes.bin` 每条为 `idx:u64 + addr:u64 + byte:u8`，小端 17 字节。
初始快照布局及来源归因见 [内存契约](memory-completeness-design.md)。
采集 sidecar 与可重建的分析缓存不同；后者必须校验输入长度和内容指纹。

## 待实现的完整采集契约

默认以目标函数一次调用自然返回为结束条件；不以记录条数、等待时长或传输文件大小
截断。当前实现仍有这些限制及 ring 满载丢弃路径，尚不满足下述契约。

- 采集阶段仅向设备本地写入。主 trace、已启用的 sidecar、模块映射和调用元数据
  都须在设备形成自足的恢复源；host 断连不改变采集范围。
- 内存使用固定大小的批次或映射窗口。写盘不依赖 Frida JS 消息循环推进；下游
  变慢时阻塞生产端，不覆盖或丢弃记录。分段只改变存储组织，不限制总记录数。
- 采集前分别以目标进程身份验证写入、以回传执行者身份验证读取，包含文件创建、
  写入、同步和读取。设备 manifest 保存实际路径、身份及文件清单；回传不得按包名
  猜路径，也不得在采集途中静默换目录。
- 调用返回后停止新增记录、排空所有批次并同步文件，再生成封口 manifest。
  之后才分段压缩和回传；回传不依赖目标进程或 Frida Script 继续存活。
- 每段包含序号、记录区间、原始字节数和摘要；压缩文件另有长度与摘要。host 解压
  校验后原子提交，最终拼装为现有 272 字节记录的 `trace.bin`。中断只重传缺失段，
  不重新执行目标函数；设备源数据在完整验证并确认之前不得删除。
- 存储不足或 I/O 错误进入明确的阻塞/故障状态，不丢记录继续执行。崩溃、强制
  终止和未封口文件只能标记为未验证完整；不能以文件存在或末尾出现 `ret` 替代
  整次采集及 sidecar 的完整性证据。

原生分块 writer 与文件映射窗口的取舍尚待慢盘、生产端阻塞、进程退出和恢复压力测试；
这些验证完成前不能宣称无损采集。实现进度只在 `TODO.md` 维护。
