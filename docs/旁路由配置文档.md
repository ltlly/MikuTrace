# 旁路由 + Clash 透明代理 配置文档

> 设备: AMD Ryzen 7 7840H / 64GB / RTL8125 2.5GbE + MT7921K Wi-Fi 6E
> IP: 192.168.5.26/24 (静态) | 网关: 192.168.5.1
> Clash 客户端: mihomo-party (Clash.Meta v1.19.21)

## 架构

```
互联网
  ↕
主路由 (192.168.5.1)
  ↕ Wi-Fi
本机 wlp2s0 (192.168.5.26) ← 静态 IP
  │
  ├─ TUN 虚拟网卡 (Mihomo, 198.18.0.1/30)
  │     ↓ 本机所有出站流量自动经过
  │  Clash.Meta (mihomo-party)
  │     ├─ GEOIP:CN → DIRECT (家宽直连)
  │     ├─ DOMAIN-KEYWORD:anthropic,claude → 代理节点
  │     ├─ DOMAIN-KEYWORD:openai → 代理节点
  │     └─ MATCH → 漏网之鱼 (默认代理)
  │
  ├─ TPROXY (7893) → nftables 拦截
  │     ↓ 其他设备的转发流量
  │
  └─ nftables TPROXY → Clash → 同上规则分流

其他设备 (网关=192.168.5.26) ──────────┘
```

## 已配置的组件

### 1. Clash 侧 (mihomo-party)

| 配置项 | 值 | 作用 |
|--------|-----|------|
| `mixed-port` | 7890 | HTTP+SOCKS 混合代理，*:7890 |
| `socks-port` | 7891 | SOCKS5 代理，*:7891 |
| `port` | 7892 | HTTP 代理，*:7892 |
| `tproxy-port` | 7893 | TPROXY 透明代理 |
| `allow-lan` | true | 允许局域网设备使用代理 |
| `tun.enable` | true | TUN 虚拟网卡，本机透明代理 |
| `dns.enhanced-mode` | fake-ip | DNS 分流，fake IP 198.18.0.1/16 |

### 2. 系统侧

| 组件 | 路径/值 | 作用 |
|------|---------|------|
| 静态 IP | `nmcli`, `192.168.5.26/24` | 防止 DHCP 换 IP 导致旁路由失效 |
| IP 转发 | `/etc/sysctl.d/99-miku-router.conf` | `net.ipv4.ip_forward=1` |
| TPROXY 路由 | `fwmark 1 → table 100 → lo` | 标记的包走本地回环 |
| nftables TPROXY | `table inet miku_router` | 拦截转发流量→7893 |
| 内核模块 | `/etc/modules-load.d/miku-router.conf` | `nf_tproxy_ipv4/ipv6` |
| 自动补丁 | `systemctl --user miku-router-patch.timer` | 每 2 分钟检查并修复 Clash 配置 |

### 3. 持久化文件

```
/etc/sysctl.d/99-miku-router.conf        # ip_forward
/etc/modules-load.d/miku-router.conf      # TPROXY 内核模块
/etc/nftables.conf                        # nftables 规则
/etc/NetworkManager/dispatcher.d/99-miku-router  # TPROXY 路由表
~/.local/bin/miku-router-patch.sh         # Clash 配置补丁脚本
~/.config/systemd/user/miku-router-patch.timer    # 定时补丁
```

## 四个问题的答案

### Q1: GUI 显示虚拟网卡是关的，但实际上在运行？

**原因**: mihomo-party 的 GUI 从 `~/.config/mihomo-party/mihomo.yaml` 读取状态，但你通过 API/直接编辑 `work/config.yaml` 启用了 TUN 模式。GUI 和 sidecar 的配置源不同步。

**当前的实际情况**: TUN 正在运行（可通过 `ip link show Mihomo` 验证）。sidecar 进程读的是 `work/config.yaml`。

**建议**: 在 mihomo-party 的 **设置 → TUN 模式/虚拟网卡** 中手动开启。这会写入 `mihomo.yaml`，下次订阅更新后配置不会丢失。

### Q2: 订阅自动更新后会覆盖我的修改吗？

**会自动更新、会覆盖、已有应对方案。**

mihomo-party 的配置生成流程：
```
mihomo.yaml (GUI 管理的基础配置)
    + 订阅数据 (proxies, rules)
    + profile.yaml
    = work/config.yaml (sidecar 实际读取)
```

当订阅更新时，`work/config.yaml` 会根据 `mihomo.yaml` 重新生成。GUI 中设置的项（allow-lan 等）会保留，但直接编辑 `work/config.yaml` 的内容会丢失。

**已部署的应对方案**:

`~/.local/bin/miku-router-patch.sh` + systemd timer：
- 每 2 分钟通过 mihomo API 检查 TUN/TPROXY 状态
- 如果被覆盖掉了，自动 PATCH 回去
- 日志: `journalctl --user -u miku-router-patch.service`

你也有订阅更新的需求，这个 timer 就是为此设计的——更新后最多 2 分钟内自动修复。

### Q3: Web 管理面板怎么访问？

mihomo-party 是桌面 GUI，不需要 web 面板。但如果你想要网页版管理界面（比如 yacd / metacubex）：

**第一步**: 在 GUI 设置中启用 "外部控制器"（External Controller），或直接编辑 `mihomo.yaml`:
```yaml
external-controller: "0.0.0.0:9090"  # 监听所有接口
```

**第二步**: 浏览器打开官方 web dashboard:
- **metacubex** (推荐): https://metacubex.github.io/metacubexd/
- **yacd**: https://yacd.haishan.me/

在 dashboard 设置中填入后端地址: `http://192.168.5.26:9090`

注意：
- GUI 设置 external-controller 后就能持久化，不会被订阅更新覆盖
- 如果只在 GUI 开但没填端口，可能不生效——需要在设置中明确指定端口

### Q4: 怎么在主路由绑定 IP？MAC 地址会变吗？

**MAC 地址不会变。**

你的 Wi-Fi 网卡 MAC: **`50:C2:E8:68:97:D7`**
你的有线网卡 MAC: **`58:47:CA:71:DC:0A`**

这是硬件 MAC（burned-in address），Linux 桌面默认使用硬件 MAC，不会随机化。只有 Android/iOS 才会默认随机 MAC。

**在主路由绑定 IP 的步骤**（以常见路由器为例）:

1. 浏览器打开 `192.168.5.1`
2. 找到 **DHCP 服务器 → 静态地址分配 / IP 与 MAC 绑定**
3. 添加一条:
   - MAC: `50:C2:E8:68:97:D7`
   - IP: `192.168.5.26`
4. 保存并重启 DHCP 或重启路由器

绑定后即使本机关机再开机，IP 也始终是 192.168.5.26。

## 验证方法

```bash
# 1. TUN 是否在运行
ip link show Mihomo

# 2. TPROXY 端口是否监听
ss -tlnp | grep 7893

# 3. nftables 规则是否正常
sudo nft list ruleset inet miku_router

# 4. IP 转发是否开启
sysctl net.ipv4.ip_forward

# 5. 代理是否工作 (应该返回 401 x-api-key required)
curl -s -w "\n%{http_code}" -X POST \
  https://api.anthropic.com/v1/messages \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{"model":"claude-sonnet-4-6","max_tokens":1,"messages":[{"role":"user","content":"hi"}]}'

# 6. 其他设备走旁路由测试 (在另一台设备上)
curl -s -w "\n%{http_code}" --connect-timeout 5 https://www.baidu.com
# 如果能通，说明旁路由转发正常
```

## 故障恢复

```bash
# 如果 Clash 挂了或被覆盖
systemctl --user start miku-router-patch.service

# 如果 nftables 规则丢了
sudo nft -f /etc/nftables.conf

# 如果 TPROXY 路由丢了 (比如 Wi-Fi 重连后)
sudo /etc/NetworkManager/dispatcher.d/99-miku-router wlp2s0 up

# 完全从头重建 (需要用到 sudo 密码)
sudo bash -c '
  sysctl -w net.ipv4.ip_forward=1
  modprobe nf_tproxy_ipv4 nf_tproxy_ipv6
  ip route replace local 0.0.0.0/0 dev lo table 100
  ip rule add fwmark 1 table 100 2>/dev/null
  nft -f /etc/nftables.conf
'
```

## 其他设备配置

需要走代理的设备，把网关改为 `192.168.5.26`:

**Android**: 设置 → WLAN → 长按 Wi-Fi → 修改网络 → 高级选项 → IP 选"静态"或 DHCP（仅改网关）
  - 网关: `192.168.5.26`
  - DNS: `192.168.5.26`（可选，用 Clash 的 DNS 分流）

**iOS**: 设置 → 无线局域网 → 点 Wi-Fi 旁的 (i) → 配置 IP → 手动
  - 路由器: `192.168.5.26`

**其他 Linux/Mac**: 
```bash
# 临时测试
sudo ip route replace default via 192.168.5.26
# 永久配置：在 NetworkManager 中改网关
```
