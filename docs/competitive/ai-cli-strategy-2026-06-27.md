# traceMiku 战略(修订)：运行时真相 CLI，工具中立，靠 (SO,偏移) 坐标缝合

> 2026-06-27 修订。前提：消费者是**任意**静态分析前端 —— AI 调 `bn-cli`/
> `ida-rs-cli`，**或逆向工程师直接在 IDA / BN / Ghidra 的 UI 里手看**。
> traceMiku **不耦合任何一个具体工具**；它只承诺一件事：用所有反汇编器都显示、
> 人能直接读写的 `(模块/SO, 静态偏移)` 坐标进出。本文取代
> `positioning-2026-06-27.md` 里"以自研反编译器为护城河"的路线图。

## 前提：静态轴已被成熟工具占满（不论 CLI 还是 UI）

无论 AI 走 `bn-cli`/`ida-rs-cli`，还是人坐在 IDA/BN/Ghidra 前面，静态分析这
一整轴都已经被这些工具做满了：任意地址反汇编(含**未执行**代码)、反编译
(HLIL→C)、静态 CFG、完整 xref、类型/结构体/字符串/导入、脚本逃生舱
(IDAPython / BN `py exec` / Ghidra script)。具体走哪个前端（CLI 还是 UI、
哪家工具）对 traceMiku 透明。

**推论**：traceMiku 不应再投入反编译器(LLIL/MLIL/HLIL→C)、静态反汇编、
静态 CFG/xref —— 这些成熟静态工具全有，且其反编译质量我们追不上。自研 IL 只
作为内部分析引擎(驱动 taint/数据流)保留，不作为对外产品面。

## traceMiku 的唯一定位：静态工具结构上给不了的运行时真相

任何纯静态前端(IDA/BN/Ghidra，不论 CLI 还是 UI)都**永远**无法回答下面这些
问题，而它们正是 traceMiku 的全部价值：

| 在静态工具里撞的墙 | 为什么静态答不了 | traceMiku 能给 |
|---|---|---|
| `br x8` / `blr x8` / 跳表 实际跳到哪 | 静态只能看到"间接" | 每条执行边的真实目标 + 命中次数 |
| 这个寄存器/buffer 此刻是什么值 | 静态只有类型/初始值 | 任意 PC 处的真实寄存器/内存值 |
| 加密/自解密/自修改的代码与数据 | 磁盘上是密文 | 运行时解密后的真实内存(快照+MemShadow) |
| 这个值从哪来的(跨函数) | 静态数据流断在调用边界 | 真实执行的反向 taint/lineage |
| 哪些分支真的跑了 | 静态所有路径都"可能" | 真实路径/覆盖率，塌缩 CFG 歧义 |
| 调用实参 / syscall 行为 | 静态只能推原型 | 每次调用的 x0–x7 真值、syscall 参/返回 |

**交汇点 = `(SO, 静态偏移)` 坐标 —— 一个工具中立的媒介**。不论是 AI 调
某个静态 CLI，还是工程师肉眼在 IDA/BN/Ghidra UI 里读，他们看到的、能跳转的、
能记下来的，都是 `libfoo.so + 0x57a30` 这种"模块+静态偏移"。这是所有反汇编器
共有的、人也能直接读写的坐标。所以 traceMiku 只要保证**用这个坐标进、用这个
坐标出**，就能和任意静态前端缝合 —— 不依赖任何特定工具的 API/插件/CLI。

工程师在 BN 里看到 `libsgmainso+0x57a30` 有个 `br x8`，直接把这个偏移敲给
traceMiku 问「实际跳哪」，拿回 `libsgmainso+0x6b20`(命中 152 次)，再回 BN
的地址栏跳过去 —— 全程零工具耦合，靠的就是这个共享坐标。**这条坐标缝合链
是一切的前提。**

## 实现优先级

排序准则：(在静态工具里撞墙的频率) × (只有运行时数据能解) × (我们已有数据、
打磨成本低)。

### P0 — 地址互操作地基（没有它，下面全都接不上静态前端）
每个 traceMiku 查询都要能用 `(so, 偏移)` 作为一等入口，并在输出里回带
`(so, 偏移)`。现状：trace 以 PC/idx 为中心，偏移解析依赖 maps/--so。
要做的是把"SO+偏移"提成统一的查询键和输出键，让人或 AI 在 traceMiku 和任意
反汇编器(CLI 或 UI)之间无缝换坐标。
价值：极高（是胶水）。难度：低-中（resolve-* 已有，需统一包装）。

### P0 — 间接跳转/调用解析
给一个有 `br/blr` 的偏移，返回真实跳转目标分布 + 命中次数。**这是静态逆向
混淆/优化代码最高频的墙**，且是纯运行时事实。数据全在 trace 里（每条执行边）。
价值：极高。难度：低（数据已有，缺一个面向"偏移→目标分布"的命令）。

### P0 — 运行时解密内存/代码导出
把运行时解密后的真实字节按 `(so, 偏移, 范围)` 导出，让使用者喂回反汇编器
(IDA loadfile / BN patch / Ghidra import) 重新分析，或直接读。基础已落地
（`--snapshot-mem` + MemShadow 的 `i` 层 + `mem-dump` 带 provenance）。
剩：偏移键化 + 一个"导出解密段"的命令。
价值：极高（壳/VMP/libsgmainso 的关键）。难度：低（地基已建）。

### P0 — 运行时值点查（寄存器/内存）
"偏移 X 处 x0 是什么 / 这个 buffer 是什么字节"。已有 `reg-value-at`、
`mem-dump`、`byte-writer-map`、`reg-timeline`。剩：偏移键化 + provenance 标注
(w/r/x/i/??，已实现)。价值：高。难度：极低（补文档+键化）。

### P1 — 反向数据流/lineage（按真实执行）
"这个值/这段密钥从哪来"——跨函数真实 taint。已有 `taint-bwd`、`bfs-slice`、
`byte-lineage`、`forward-dep-tree`。这是 crypto/签名逆向的杀手锏，静态工具的
函数内数据流(如 BN `uidf`)断在调用边界、且无真实值。价值：高。难度：低（已有，键化+示例）。

### P1 — 路径覆盖
"哪些分支真跑了"，把静态前端展示的全路径 CFG 塌缩到真实执行路径。已有 `loops`、
`call-tree`、`call-chain`。补一个"覆盖率/已执行边"视图。价值：中。难度：低。

### P1 — 内存完整性 Phase 2（syscall/JNI 回读）
给上面的"解密内存/运行时值"补齐内核写的 buffer(read/recv/stat/getrandom)。
设计见 `memory-completeness-design.md`。价值：中高。难度：中。

### P2 — 行为日志（syscall/JNI 实参与返回）
malware/SDK 行为分析的 ground truth。已有 semantic events 雏形。价值：中
(看目标)。难度：中。

## 明确不做（在此前提下）
- 自研反编译器作为产品面 —— IDA/BN/Ghidra 已给更好的反编译。
- 静态反汇编 / 静态 CFG / 静态 xref —— 成熟静态工具全有。
- trace 导航 UI（对标 Tenet）—— 与"运行时真相 CLI"定位无关。
- 耦合任何特定静态工具的 API/插件/CLI —— 只认 `(SO, 偏移)` 中立坐标。
- MCP —— 项目原则 + 用户用 CLI/UI。
- 把"每秒多少行吞吐"当头条去和 GumTrace 硬拼。

## 一句话战略（修订）

> 静态轴(代码/CFG/xref/反编译)已被 IDA/BN/Ghidra 占满，不论用 CLI 还是 UI；
> traceMiku 不竞争，而做**工具中立的运行时真相 CLI** —— 专答间接跳转、运行时
> 真值、解密内存、真实数据流、执行路径这些静态结构上答不了的问题。使用者(人或
> AI)在任意反汇编器里读代码、在 traceMiku 取运行时事实，两边只靠 `(SO, 偏移)`
> 这个所有工具共有的坐标缝合，不绑定任何一家。
